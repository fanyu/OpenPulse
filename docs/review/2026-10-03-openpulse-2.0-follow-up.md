# OpenPulse 2.0 — follow-up correctness and performance review

The accepted dashboard/menu-bar redesign and first review were committed as `d677235`. This follow-up examines account storage, refresh ownership, desktop-to-iPhone snapshots and large Activity histories. All account/API tests use synthetic credentials and injected transports; no real account switch, authorization, notification, CloudKit publication or local-tool history import was performed.

## Confirmed repairs

| Area | Defect and repair |
| --- | --- |
| Codex stored accounts | Legacy account JSON encoded complete authorization material. Version 2 encodes metadata only and hydrates authorization from Keychain. Migration validates identities and verifies every credential read-back before atomically replacing the legacy file; failure preserves the old file. |
| Codex account mutations | Corrupt metadata became an empty store; failed saves could lose credentials. Reads now throw, duplicates/identity mismatches are rejected, failed metadata writes restore prior credentials, and active-account deletion is rejected. |
| Codex concurrent usage | An awaited usage response could resurrect deleted accounts or overwrite imports/rotated credentials. Completion reloads current metadata and merges only still-present accounts with unchanged authorization. |
| Codex restart | Overlapping automatic switches could each restart Codex; waiting before draining a subprocess pipe could deadlock on large output. Automatic switching owns its operation before awaiting, and process output is drained before waiting for exit. |
| Codex switch policy | Failed, stale, unknown, exhausted or expired preserved quotas could determine an automatic account switch. Decisions now require successful observations within ten minutes, valid percentages and future reset dates; automatic switching requires reliable current-account exhaustion. Explicit account switching remains available without quota data. |
| Menu-bar switch failures | A failed restart could leave the displayed active account inconsistent with the authorization already written. Failure handling reloads metadata without performing another switch or network refresh, then displays the original error. |
| Fast/local refreshes | Bridge, local Codex quota and individual Antigravity refresh paths bypassed tool ownership and post-refresh propagation. They share the refresh gate, advance successful timestamps only after accepted persistence, and propagate desktop snapshots/pushes consistently. Bridge-only work remains local. |
| File events | Events arriving during an owned refresh could be dropped. Bounded pending work catches up after ownership ends; stop/cache clear cancel pending work. Claude Desktop events and daily totals now use the same local import path. |
| Codex local quota cache | A single newest-file timestamp missed appended, replaced, added or deleted quota sources. Cache identity now includes per-file modification time, size and resource identity, reduces to the current source set, and retries failed reads. |
| Antigravity partial failure | A quota failure prevented local tasks from saving; a partial account response removed still-authorized accounts. Local sessions save before quota work, while quota errors still surface. Partial responses retain failed credentialed accounts with their old observation time, and removed credentials prune accounts. |
| CloudKit snapshot updates | Saving a fresh record with the fixed `current` identifier could conflict after the first publication. Changed-key record modification supports later publications and checks each returned record result. |
| Snapshot meaning | Weekly exhaustion could overwrite the displayed session allowance; old Claude data could be stamped fresh by republishing. Session and weekly windows remain separate, expired/unknown windows are stale, and Claude's actual observation date survives caching and publishing. |
| iPhone state | Timer ticks erased fetch errors; old envelopes and expired reset windows could still present fresh/exhausted state. Fetch errors persist until recovery, freshness controls pet presentation, and expired windows wait for refresh. Corrupt key-value data falls back to CloudKit; concurrent fetches coalesce and older/missing results cannot replace the last known snapshot. Duplicate automatic bootstrap was removed. |
| Activity execution | The main actor hydrated an all-history query, fetched the same history again, mapped rows and searched them. Fresh model actors now materialize immutable Sendable snapshots off main, with background summaries/indexes/search and cancellation/generation checks. |
| Activity list rendering | Passing every row to native List still caused long ID/diff updates after background search. Rendering starts at 200 rows, grows only when the footer enters the viewport, and retains full search/statistics/selection. Show all restores the complete scrollbar range. Late footer callbacks cannot expand a different query. |

## Synthetic performance measurements

Release fixtures used 50,000 sessions across 365 days; Activity includes 49,270 Codex/Claude sessions. Baseline is `d677235`; the final comparison changes Activity's implementation while retaining the same synthetic data construction, isolated home, rejected network and mocked credentials. Fixture seeding is excluded from the operation timings.

| Measurement | Baseline | Background work only | Final bounded list |
| --- | ---: | ---: | ---: |
| Activity full snapshot read | 929 ms on main | 809 ms off main | 861 ms off main |
| Snapshot application | Included above | 0.071 ms | 0.064 ms |
| First-load maximum main-queue delay | 2,650 ms | 310 ms | 295 ms |
| Search computation, `Project-15` | 114 ms on main | 103 ms off main | 127 ms off main |
| Search maximum main-queue delay | 273 ms | 282 ms | 358 ms |
| Post-search RSS sample | 784.6 MiB | 570.8 MiB | 253.3 MiB |

The first-load probe improved substantially in this case. The search probe **does not establish an interaction speedup**; its worst delay remains an open rendering/interaction concern. Search still covers all history and returned the same 1,214 matches. Background read duration is similar; the improvement comes from moving that work away from the main actor and reducing eager row work.

The main-queue probe schedules 600 main-actor sleeps of 16 ms and measures excess delay. It includes the native UI/accessibility exercise and machine scheduling. These are single runs with other project work present on the Mac. RSS is a single sample, includes retained fixture construction, and is not peak memory or process physical footprint. See the [metrics file](openpulse-2.0/performance-50000-synthetic.json) for values and limitations.

Separate Time Profiler captures resolved all XML backtrace/frame references. Baseline main-thread sampled weight included 855 ms in Activity snapshot refresh, 844 ms in row initialization and 532 ms in the all-session query getter; inclusive weights overlap. After background processing, Activity read/materialization/aggregation/search had zero main-thread samples, and those operations appeared on background threads. The intermediate capture still showed native List row diffing (83 ms inclusive), cell configuration (48 ms) and SwiftUI/accessibility work. Capture spans differ, so sampled weights are hotspot evidence rather than directly comparable wall-clock speedups. Raw traces remain outside the repository and no trace environment metadata was exported into the report.

## Remaining acceptance and limitations

- Live OAuth, real account restart, real Keychain migration, API responses, CloudKit transfer, login registration and OS notification delivery still require runtime acceptance. Build/test success is not evidence of those operations succeeding.
- Inactive Codex accounts retain imported access tokens and do not yet renew expired authorization. The upstream [managed authentication implementation](https://github.com/openai/codex/blob/main/codex-rs/login/src/auth/manager.rs) owns renewal and persistence. Safe integration with that lifecycle remains open; this pass does not independently rotate credentials used by another Codex process. Failed/stale quota cannot drive an automatic switch after this patch.
- External processes do not participate in the app's file/credential transaction gate; an uncoordinated external writer can still race during the short read/atomic-write interval.
- The performance fixtures use an in-memory store and retain the seeding context. Memory includes fixture construction. Measurements establish this synthetic case, not production peak memory, disk-store latency, live polling cost or every history size.
- Explicitly choosing Show all restores full native List enumeration and its cost. Automatic browsing keeps row rendering bounded as the user scrolls.
- Existing randomly identified Antigravity cache duplicates are preserved. No private cache, user configuration, credential or unrelated change was deleted.
- No signed distribution, version bump, release, upload or push was performed.
